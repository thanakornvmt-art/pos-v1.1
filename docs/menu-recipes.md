# สูตรรายเมนู

เปิด **สูตรและต้นทุน > สูตรรายเมนู** เพื่อค้นหาด้วยชื่อหรือรหัสเมนู กรองหมวดหมู่/สถานะ และเพิ่มสูตรให้เมนูที่มีอยู่ เมนูใหม่ยังใช้หน้าสร้างเมนูเดิมและปิดขายไว้ก่อน

สูตรใช้ปริมาณต่อ 1 หน่วยขาย เลือกวัตถุดิบหรือสูตรย่อยจากฐานข้อมูล หน่วยใช้มาจากวัตถุดิบ/ผลผลิตสูตรย่อยโดยตรง ไม่เปลี่ยนหน่วยสต็อก ปริมาณรองรับทศนิยมไม่เกิน 6 ตำแหน่งตาม Decimal(18,6) เดิม บรรจุภัณฑ์กำหนดแยกตามช่องทางและไม่ควรใส่ซ้ำในสูตรหลัก

ตัวเลือก/รูปแบบสินค้าที่ผูกกับเมนูเดิมใช้จำลองต้นทุนและราคาขาย การเลือกในหน้าสูตรไม่เปลี่ยนตัวเลือกส่วนกลางหรือเพิ่มส่วนประกอบซ้ำ ต้นทุนใช้ค่าเฉลี่ยปัจจุบัน กำไรหักค่าธรรมเนียมช่องทางและบรรจุภัณฑ์ แต่ยังไม่หักค่าแรงและค่าใช้จ่ายร้าน

การบันทึกและลบต้องยืนยัน เจ้าของร้านเท่านั้นที่แก้ได้ การลบสูตรลบ BOM และบรรจุภัณฑ์ของเมนู พร้อมปิดขาย เก็บเมนู ราคา ตัวเลือก และประวัติไว้ เมนูไม่มีสูตรเปิดขายผ่าน API จัดการไม่ได้ บันทึก audit log ในธุรกรรมเดิม และตรวจรุ่นสูตรก่อนบันทึกจากหน้าจอใหม่เพื่อป้องกันทับการแก้จากเครื่องอื่น

ไม่มีตารางหรือ migration ใหม่ การจัดการสูตรไม่สร้าง stock movement ไม่เปลี่ยนยอดวัตถุดิบ บิลเก่า หรือต้นทุนที่บันทึกแล้ว CatalogSnapshot เดิมยังคงเดิม บิลออฟไลน์ใช้ชุดสูตรตอนขายและส่งซ้ำไม่ตัดสต็อกซ้ำ เครื่องออฟไลน์ต้องเชื่อมต่อและรับข้อมูลใหม่ก่อนใช้สูตรใหม่

ทดสอบด้วยฐานข้อมูล localhost ที่แยกจากร้าน: เพิ่ม/แก้/ลบและยกเลิกการยืนยัน, สูตรย่อย/หน่วยใช้, บรรจุภัณฑ์, สิทธิ์, validation, รุ่นสูตรเก่า, audit log, ยอดสต็อกไม่เปลี่ยน, snapshot เก่า/การส่งบิลซ้ำ และหน้าจอ 320, 390, 667, 768, 1280 พิกเซล ร่วมกับการทดสอบสร้างเมนูและสถานะขายเดิม
